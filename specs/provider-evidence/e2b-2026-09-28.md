## Reproduction and diagnostic limits

The harness uses `AdapterSandbox.writeFile` / `readFile` through the bound public `e2b` factory. The destination below is a placeholder for the owned test file; no resource identifiers are included.

```ts
const path = "/tmp/<owned-test-file>";
const first = new Uint8Array([0, 255, 1, 128]);
const second = new Uint8Array([2, 254, 0]);

await sandbox.writeFile(path, first, { overwrite: true, signal });
// Initial read matched first: passed.
await sandbox.writeFile(path, second, { overwrite: true, signal });
// Overwrite scenario requires readFile(path) to match second exactly, including length.

// No-clobber scenario requires this write to throw SandbarError with code CONFLICT:
await sandbox.writeFile(path, first, { overwrite: false, signal });
// After the conflict, readFile(path) must still match second exactly.
```

The original runner recorded both scenario checks as failed with `assertion-failed`. Its report did not retain per-assertion error text or actual bytes. During evidence review, the no-clobber qualification row was corrected to `blocked` / `dependency-failed`: its prerequisite overwrite had failed, so its combined check cannot establish an independent no-clobber result. The original immutable runner report remains private, and this correction does not claim that another live check ran. Thus the observed facts are the overwrite failure and a dependent check failure; actual returned bytes and the failing sub-assertion are unavailable. Do not infer that trailing bytes survived, that no-clobber dispatched a successful write, or that either specific provider defect has been proven. The no-clobber scenario follows the failed overwrite, so its failure may depend on the earlier file state.

The merged provider's overwrite path calls `transport.write` directly; the native transport calls `sandbox.files.write(path, new Blob([bytes]), { requestTimeoutMs: 30_000 })`. The no-clobber path writes an owned staging file, runs `ln -T` without replacement, maps `EXISTS` to `CONFLICT`, and removes the staging file. Offline qualification uses a local fixture whose `writeFile` replaces the file contents; all offline and packed checks passed before this live run. The runner now skips dependent file scenarios when prerequisites fail, covered by an offline fixture; this change was not rerun live. The E2B owner should diagnose native transport/file semantics and assess the harness assertion chain offline. No parallel adapter edits or further live resources are authorized by this evidence.

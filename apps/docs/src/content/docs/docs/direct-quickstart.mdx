Run a command in a sandbox from your own TypeScript application. You'll need a provider account and **Bun** to run this example. The SDK also supports server-side [Node.js](/docs/providers/support/#runtimes).

## 1. Set up a checkout

Sandbar packages are not published yet. Use **Bun 1.3.14** and run from a source checkout:

```sh
git clone https://github.com/pandemicsyn/sandbar.git
cd sandbar
bun install --frozen-lockfile
bun run build:packages
```

Already in a checkout? Run the install and build commands from its root. The workspace resolves `sandbar-sdk` and the separate experimental `sandbar-modal` adapter locally. Modal has offline coverage and has not been live-qualified; [compare provider support](/docs/providers/support/).

To run OpenCode rather than a shell command, use the [runnable agent examples](/docs/guides/runnable-agent-examples/).

## 2. Add your credentials

Create an untracked `.env.local` file in the repository root:

<Tabs syncKey="quickstart-provider">
  <TabItem label="Daytona">

```sh title=".env.local"
DAYTONA_API_KEY="<your-daytona-api-key>"
```

The example uses the `daytona-small` Linux snapshot in `us`. Select an active snapshot available in your region. `daytona-default` permits Daytona's essential services; it does not mean all egress is blocked.

  </TabItem>
  <TabItem label="E2B">

```sh title=".env.local"
E2B_API_KEY="<your-e2b-api-key>"
```

The example uses E2B's public `base` template. No team ID or custom template is required.

  </TabItem>
  <TabItem label="Modal (experimental)">

```sh title=".env.local"
MODAL_TOKEN_ID=your-modal-token-id
MODAL_TOKEN_SECRET=your-modal-token-secret
MODAL_APP_NAME=your-existing-app
MODAL_IMAGE_ID=im-your-existing-image-id
```

Use an existing Modal App in the `main` environment and an existing prepared image containing `/bin/sh` and standard shell utilities. The example does not create an App or build an image.

  </TabItem>
</Tabs>

Add `.env.local` to your `.gitignore`. Keep credentials on the server and out of browser code. Running the example creates a sandbox in your provider account and may incur usage charges.

You should see `Hello from Sandbar!`. Each example destroys the sandbox in `finally`, then closes the client. `close()` alone does **not** destroy compute. If creation or cleanup has an uncertain outcome, follow [Errors and recovery](/docs/guides/recovery/) before retrying.

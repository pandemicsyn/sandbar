# boxd completeness audit

Audited against remote main (including merged docs PR #97), current Sandbar contracts, official boxd docs/protobuf, and the **published** `@boxd-sh/sdk@0.2.15` tarball installed by the frozen lockfile. Registry latest remains 0.2.15; no upstream-only API is assumed. Research issue #41 is historical input. No hosted calls were made for this audit.

| Existing API                                          | Result and native boundary                                                                                                                                                                                                                                                                                                         |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Buffered exec / finite stdin                          | Implemented byte frames and EOF via the published Exec protobuf; max 1 MiB input/output, 64 KiB input frames. Existing argv/cwd/env and cancellation drain retained.                                                                                                                                                               |
| stat / exists / recursive mkdir / nonrecursive remove | Implemented finite Python 3 helper. lstat default, dangling links exist, recursive opt-in, no recursive fallback for nonrecursive remove.                                                                                                                                                                                          |
| copy / move / no-clobber                              | Implemented regular-file copy with same-directory staging/hardlink publish, native same-filesystem rename, Linux renameat2 no-clobber. Buffered exclusive-create write uses O_EXCL and finite native stdin without hidden staging.                                                                                                 |
| Large streams / traversal / text lines                | Implemented incremental 64 KiB helper reads/writes; staging, backpressure and retained failure paths. SDK walk/text-line composition is available. No immutable read snapshot or mounted-storage qualification.                                                                                                                    |
| Disks / mounts / warm lifecycle                       | Already implemented, not live-qualified. Added exact read-only mount, fresh-client explicit disk cleanup, hibernation wake and single-attempt coverage.                                                                                                                                                                            |
| Images / resources                                    | OCI boot remains supported. Optional native 1/2/4/8 vCPU size class; RAM follows native class, fixed 100 GB private disk. Region/labels/prepared builds unsupported; no published image-build artifact API.                                                                                                                        |
| Public preview                                        | Implemented explicit public setup with pinned create-time ports; browser protection disabled after expiry install. Read-only exact-machine route lookup. No auto-port routing, protected-header credentials or implicit exposure changes during lookup.                                                                            |
| Snapshots                                             | Native latest-only generations are replaced; get/delete/restore selectors lack expected-version targeting. Exact saved capture/restore/delete remains unsupported before effects. Native memory capture does not establish immutable artifact identity.                                                                            |
| Processes / streaming / PTY / signals / reopening     | Native exec supports interactive traffic but cancellation closes/kills its process group; no persistent exact-generation attach handle. A bounded finite helper does not supply detach/reopen or persistent output custody. A durable guest supervisor is outside the permitted small-helper approach; no such guarantees claimed. |
| Network policy                                        | Internet-only. Empty allowlist is unrestricted, host-bound secrets are additional exceptions, and applying an allowlist after create cannot guarantee blocked egress from first execution. No guest-firewall substitute.                                                                                                           |

Primary evidence: [published SDK reference](https://docs.boxd.sh/reference/typescript-sdk), [protobuf API](https://docs.boxd.sh/reference/grpc-proto), [snapshots](https://docs.boxd.sh/guides/snapshots), [proxies](https://docs.boxd.sh/guides/proxies), [resources](https://docs.boxd.sh/guides/resources), [egress](https://docs.boxd.sh/guides/egress).

Local guest filesystem tests execute Python 3 against owner-created temporary directories. Protobuf fixtures separately exercise actual codecs/request construction and native stream EOF. They are distinct from hosted qualification. On macOS, Linux renameat2 absence is tested as effect-free unsupported; Linux CI exercises its successful path. No live pass is inferred from any fixture or packed check.

## Proposed live qualification — not authorized or run

Use the existing ordinary Bun suites/profile and persistent owner-only ledger. Run sequentially, without creator retries or image builds, against a borrowed Linux OCI image with Python 3. Configure 1 vCPU / 4 GiB, explicit internet policy and native 900-second expiry; public-preview invocation explicitly selects `SANDBAR_BOXD_PREVIEW_ACCESS=public`, with ports 3000/3001 pinned by the profile. No protected preview/network isolation/snapshot/process claim is tested.

Proposed maxima: **8 compute allocations total, peak 1; 2 independent disks total, peak 1 (1 GiB each); zero snapshots/builds**. Select finite-stdin, expanded file-directories (32 MiB hash-checked stream plus traversal/text lines), public-preview, suspend/resume, renewal, disk CRUD and mounted persistence cases only. Exact case selection and aggregate ledger bounds must be checked before authorization. Extend the qualification configuration metadata to record native size and preview access/ports before collecting new live evidence; the historical schema does not capture those settings. Each fixture: setup at most 30 seconds, exercise at most 240 seconds, cleanup at most 60 seconds plus client release; total sequential observation budget at most 45 minutes. Compute's native TTL is fallback, not a disk cleanup receipt. At most 32 MiB test data per active filesystem workflow; no disk expiry exists. This resource/time budget is not a dollar-price guarantee; use current account pricing before approving cost.

Awaited pre-dispatch ledger records own creators. Delete only exact acknowledged owned identities, destroy compute before disk deletion, verify teardown/retained disk deletion and close clients. On timeout/failure, stop later creators and attempt owned cleanup within the budget. On process interruption reconcile the existing ledger with current credentials; never replay create/delete/publish or adopt names. Preserve uncertain disk creators and deletion receipts. All new features stay live not-run until reviewed JUnit and cleanup provenance exist. The `fcb59d4` baseline remains exactly lifecycle, captured execution, native binary overwrite/read and reopening.

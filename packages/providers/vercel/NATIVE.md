# Native boundary provenance

Audited October 11, 2026 against the published `@vercel/sandbox@3.6.1` archive, downloaded without executing package code:

- Archive: https://registry.npmjs.org/@vercel/sandbox/-/sandbox-3.6.1.tgz
- Integrity: `sha512-U6dwyadp2SmW/M96W2Bb3UjIql6TOOYwu9McUIwob209pj0A3ks/wKrMv7lCE7INx50J5zOpqLhMOnFa+Yodlg==`
- Inspected emitted `api-client/api-client.js`, `validators.js`, `base-client.js`, `with-retry.js` and `utils/network-policy.js`.
- Upstream reference: https://github.com/vercel/sandbox/tree/31244aa3280dc3fdca0680933f85971570d73d2d
- Implementation brief: https://github.com/pandemicsyn/sandbar/issues/28

`@sandbar-sdk/vercel` implements the public `@sandbar-sdk/adapter` API and owns HTTP construction; it does not import SDK internals or install the native SDK. Every request uses the fixed `https://vercel.com/api` origin, explicit team routing, redirects disabled and one fetch dispatch. Injectable transports are trusted host code and must not retry mutations.

Creation uses `/v3/sandboxes`; session detail/stop, command detail/logs and binary filesystem routes use `/v2/sandboxes/sessions/{id}`. Project ownership reads use `/v2/teams/{teamId}` and `/v2/projects/{projectId}`. Collection queries use `project`, rather than uniformly substituting `projectId`. Reopened IDs are checked against the project's session collection. No named lookup/resume/delete request is made. Renewal uses the immutable-session extend-timeout endpoint. Snapshot deletion uses only the immutable snapshot-ID endpoint.

This is a version-sensitive source-derived REST boundary, without an independently established public stability guarantee. Published 3.6.1 ordinary logs are strings; binary finite stdin is absent there even though the inspected upstream revision declares the same version and adds stdin support. Finite stdin therefore uses an adapter-owned bounded byte stage and pipe/EOF, without relying on upstream-only stdin. A newer SDK must be inspected as a published artifact before that assumption changes.

Guest capture launches user argv exactly once with Node 24. Only the helper's private receipt path and validated exit-status marker enter text logs; user stdout/stderr remain bytes, bounded together before base64 encoding and binary-file retrieval. Malformed/incomplete receipts fail closed. Read-only recovery never reinstalls or launches the helper. Receipts remain until disposable-session teardown. Acknowledged command identity remains saved if retrieval fails. Once the helper exit marker is validated, `confirmedExit` is checkpointed in the existing execution recovery token before output-file retrieval. A retrieval failure preserves that exit in the public operation recovery reference without claiming complete output or extending the SDK API. Later read-only recovery rejects conflicting exit evidence; a lost initial command acknowledgement remains unknown. Local abort does not establish remote termination.

Only `stopped` and `aborted` are treated as terminal compute evidence; `failed`, absence and response loss do not certify cleanup. Reusable-name deletion has no proven generation precondition. Named metadata remains retained. No live observations are implied by this audit or deterministic fixtures.

## Completeness audit

Capture preparation checks exact current-session project metadata, disposable mode, managed Node image and no mounts. Saved capture references retain observed mount/consistency provenance for later inspect/restore; generic native inventory has unknown mount provenance. No reference field substitutes for project/region authorization. Snapshot ACKs and mutation tokens preserve identities independently of later reads. A source-session match alone is not native operation correlation and cannot justify deleting an artifact after a lost capture ACK.

Control helpers emit bounded machine JSON; byte output enters logs only after base64 encoding in the supervisor. Filesystem and process RPCs do not create capture receipt files. Ordinary finite-exec receipts remain available for read-only recovery until compute teardown. Native logs/caches are provider-owned; adapter queues and per-request bodies remain bounded. Public regions/images are documented at https://vercel.com/docs/sandbox/concepts/regions and https://vercel.com/docs/sandbox/concepts/images; snapshot and drive behavior at https://vercel.com/docs/sandbox/concepts/snapshots and https://vercel.com/docs/sandbox/concepts/drives. No paid/live experiment was performed.
